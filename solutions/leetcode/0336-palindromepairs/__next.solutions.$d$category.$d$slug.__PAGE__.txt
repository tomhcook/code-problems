3:T824,<h1>Palindrome Pairs</h1>
<p>Given a list of unique words, find all pairs of distinct indices <code>(i, j)</code> in the given list, so that the concatenation of the two words, i.e., <code>words[i] + words[j]</code> is a palindrome.</p>
<h2>How the Solution Works</h2>
<p>A brute-force solution checks all pairs, which takes $O(N^2 \cdot L)$ time (where $N$ is the number of words and $L$ is the maximum length of a word). This is too slow for the constraints ($N \le 5000$).</p>
<p>An optimal approach uses a <strong>Hash Map</strong> to store each word and its index, allowing $O(1)$ lookup time:</p>
<ol>
<li>We populate a hash map mapping each word to its index.</li>
<li>For each word <code>words[i]</code>, we split it into all possible prefixes and suffixes <code>word[:j]</code> and <code>word[j:]</code> for $j \in [0, L]$.</li>
<li>For each split:<ul>
<li><strong>Case 1:</strong> If the prefix is a palindrome, we check if the reverse of the suffix exists in our hash map. If it does (and is not <code>i</code>), then <code>reversed(suffix) + word</code> (i.e. <code>words[idx] + words[i]</code>) forms a palindrome.</li>
<li><strong>Case 2:</strong> If the suffix is a palindrome, we check if the reverse of the prefix exists in our hash map. If it does (and is not <code>i</code>), then <code>word + reversed(prefix)</code> (i.e. <code>words[i] + words[idx]</code>) forms a palindrome. To avoid double-counting the full-word reverse pairs (which are handled when the prefix is empty in Case 1), we only apply Case 2 when the suffix is non-empty (<code>j &lt; L</code>).</li>
</ul>
</li>
</ol>
<h2>Complexity</h2>
<ul>
<li><strong>Time Complexity:</strong> $O(N \cdot L^2)$ where $N$ is the number of words and $L$ is the maximum length of a word. For each of the $N$ words, we perform $L$ splits, and checking for palindrome and slicing takes $O(L)$ time.</li>
<li><strong>Space Complexity:</strong> $O(N \cdot L)$ to store all words and their indices in the hash map.</li>
</ul>
