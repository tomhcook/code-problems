3:T652,<h1>High-Access Employees</h1>
<p>You are given a 2D list of strings <code>access_times</code>, where each element is a list <code>[employee_name, access_time]</code>. An employee is classified as a <strong>high-access</strong> employee if they have accessed the system <strong>three or more times</strong> within any <strong>one-hour period</strong> (strictly less than 60 minutes).</p>
<p>Return a list of the names of high-access employees.</p>
<h2>How the Solution Works</h2>
<ol>
<li><strong>Group Times by Employee</strong>: We group access times for each employee using a hash map.</li>
<li><strong>Convert to Minutes</strong>: To simplify calculations, we convert the HHMM format strings into minutes since midnight (i.e., <code>HH * 60 + MM</code>).</li>
<li><strong>Sort Times</strong>: We sort the list of access times chronologically for each employee.</li>
<li><strong>Sliding Window Check</strong>: For each employee, we check if there exists an access index $i$ such that <code>times[i + 2] - times[i] &lt; 60</code>. If we find such a window, it means the employee had 3 accesses within a 60-minute window, so we add their name to the output list and move on to the next employee.</li>
</ol>
<h2>Complexity</h2>
<ul>
<li><strong>Time Complexity:</strong> $O(N \log N)$ where $N$ is the total number of accesses in the input array. Sorting the access times per employee dominates the run time.</li>
<li><strong>Space Complexity:</strong> $O(N)$ to store the grouped access times in the hash map.</li>
</ul>
